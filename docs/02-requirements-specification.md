## 機能要件一覧

| ID | 機能名 | 概要 | 優先度 |
|----|--------|------|--------|
| FR-01 | ユーザー登録 | メール / パスワード / 表示名で登録し、トークンを発行する | Must |
| FR-02 | ログイン | 認証情報を検証しトークンを発行する | Must |
| FR-03 | トークンリフレッシュ | リフレッシュトークンでアクセストークンを再発行（ローテーション） | Must |
| FR-04 | ログアウト | リフレッシュトークンを失効させる | Must |
| FR-05 | タスク作成 | 自分のタスクを作成する（開始日必須・終了日任意） | Must |
| FR-06 | タスク一覧 | 自分のタスクを作成日降順で取得する | Must |
| FR-07 | タスク詳細 | 自分のタスクを 1 件取得する | Must |
| FR-08 | タスク更新 | 指定フィールドのみ更新する | Must |
| FR-09 | タスク削除 | 自分のタスクを削除する | Must |
| FR-11 | 画像添付 | タスクに画像を 1 枚添付・差し替え・削除する（任意） | Should |
| FR-12 | API ドキュメント | 契約から生成した Swagger UI を配信する | Could |

## 受け入れ条件

- FR-01: 同一メールの重複登録は 409。パスワードは **8 文字以上・UTF-8 72 バイト以内**（bcrypt の切り捨て境界。文字数ではない）。成功時 201 でトークンを返す。
- FR-02: 認証失敗は 401。ユーザーの有無を区別しない（列挙防止）。
- FR-03: 使用済みリフレッシュトークンは無効化され、再発行される。
- FR-05〜FR-09: 未認証は 401、他人のタスク操作は 403、存在しない ID は 404。
- FR-05/FR-08: `startDate` 必須（未指定 422）、`startDate ≤ endDate`（逆転 422）、`status` は todo/in_progress/done のみ。検証失敗は `ApiError.errors` にフィールド別の理由が入る。
- FR-10: 検証成功は 200 `{ valid: true }`、失敗は通常と同じ `ApiError`。DB へ一切書き込まない。
- FR-11: MIME は png/jpeg/webp、サイズ ≤ 2MB（違反 422・`errors[].field` は `file`）。所有者のみ（403/404）。添付後 `imageUrl` が設定され `/uploads/<file>` で取得できる。

## 優先度の定義

| ランク | 意味 |
|--------|------|
| Must | これが無いと成立しない中核機能 |
| Should | 学習価値が高く実装済みだが、欠けても中核は成立する |
| Could | あると望ましい補助機能 |
